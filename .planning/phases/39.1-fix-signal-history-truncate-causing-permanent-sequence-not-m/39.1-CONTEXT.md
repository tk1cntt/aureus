# Phase 39.1: Fix Signal History Truncate Causing Permanent SEQUENCE_NOT_MATCHED — Context

**Gathered:** 2026-04-10
**Status:** Ready for planning
**Source:** Urgent debugging session — discovered signal history truncate + triggered_t interaction causes permanent strategy stall after ~4h runtime

<domain>
## Phase Boundary

Fix the interaction between `log_signal_normalize` truncation (bounded at 240 records in `state.py`) and `triggered_t` filtering (in `template.py` `_evaluate_sequence`) that causes all strategies to permanently reject with `SEQUENCE_NOT_MATCHED` after the signal history fills entirely with events older than `triggered_t`.

The service does NOT crash — it runs normally, processes candles, receives stream messages. But every strategy evaluation returns `SEQUENCE_NOT_MATCHED` because no events in the truncated history have `t > triggered_t`.

## Root Cause Analysis

**Signal History Truncation** (`state.py` line 228-229):
```python
self.log_signal_normalize.append(payload)
if len(self.log_signal_normalize) > 240:
    self.log_signal_normalize.pop(0)
```

**Triggered_T Filter** (`template.py` line 240):
```python
if triggered_t > 0 and latest_time <= triggered_t:
    continue  # skip old events
```

**Timeline of failure:**
1. Service starts → `triggered_t = 0` → all 240 events valid for matching
2. Strategy triggers → `_reset_sequence_state` sets `triggered_t = bar_t`
3. New candles arrive → signal engine appends + truncates (240 max)
4. After ~240 candles (~4h on M15 XAUUSD), ALL events in `log_signal_normalize` have `t <= triggered_t`
5. `_evaluate_sequence` skips every event → no steps matched → `SEQUENCE_NOT_MATCHED`
6. **Permanent stall** — every subsequent evaluation fails the same way

**Restart temporarily fixes it:** Executor memory resets → `triggered_t = 0` → all events valid again. But cycle repeats.

## Evidence from Production

- Last successful trigger: `2026-04-09 22:31:02 UTC` (05:31 VN) — `TREND_CONT_BEAR` on USTEC
- After that: ALL 6 strategies on ALL 8 symbols → `SEQUENCE_NOT_MATCHED` every candle
- Signal engine: still processing candles normally (logs show `execute_signals_for_candle`)
- Strategy executor: still receiving stream messages normally (938 entries, lag=0)
- Service uptime: 16+ hours, exit code 0, no crash, no OOM

<decisions>
## Implementation Decisions

### D-01: Auto-reset sequence when insufficient events remain (Recommended approach)

When `_evaluate_sequence` iterates through all events and cannot advance `current_step_index` from its current position, check if the number of usable events (t > triggered_t) is fewer than the number of remaining steps needed to complete the sequence. If so, auto-reset the sequence state (clear triggered_t, reset current_step_index to 0) so the next candle can start matching from step 0 with the full history.

**Rationale:** `triggered_t` is designed to prevent re-firing within the same cycle, NOT to block forever. When history naturally truncates consumed events, the mechanism should gracefully reset rather than deadlock.

**Location:** `services/aureus-signal/engine/strategies/template.py` `_evaluate_sequence` method, after the event processing loop.

### D-02: Add INFO-level logging for SEQUENCE_NOT_MATCHED with diagnostics

The `registry.py` already extracts `sequence_diagnostics` (missing_required_tags, current_step_index, matched_steps/total_steps, mismatch_reason) but only logs at DEBUG level. Upgrade to INFO when reason is SEQUENCE_NOT_MATCHED so operators can immediately see why strategies stall.

**Location:** `services/aureus-signal/engine/strategies/registry.py` line ~325

### D-03: Increase signal_history truncate limit from 240 to 500

240 records is too small for sequences with 3-5 steps that need lookback context. Increasing to 500 provides margin so auto-reset (D-01) triggers less frequently.

**Trade-off:** Larger payloads in Redis stream messages (~318KB → ~660KB per symbol). Acceptable for 8 symbols.

**Location:** `services/aureus-signal/engine/state.py` line 228

### D-04: Do NOT prune consumed events from signal history

Signal history is shared between the signal engine (calculates zigzag, pivots, sessions — all need contiguous lookback) and the executor. Pruning events would break signal engine calculations. Each component should manage its own view.

<specifics>
## Specific Ideas

**Auto-reset detection logic** (pseudo-code for D-01):
```python
# After event processing loop, before building progress_data
events_after_trigger = sum(1 for e in all_events if e["t"] > triggered_t)
remaining_steps = len(self.sequence) - current_step_index
if remaining_steps > 0 and events_after_trigger < remaining_steps:
    logger.warning(f"[{symbol}] [{self.name}] Auto-reset: only {events_after_trigger} "
                   f"events after triggered_t={triggered_t}, need {remaining_steps} steps")
    self._reset_sequence_state(state_obj, triggered_t=last_processed_t,
                               last_processed_t=last_processed_t,
                               internal_candle_counter=internal_candle_counter)
```

**Key constraint:** Must NOT reset if `current_step_index == 0` (already waiting for step 0) — that's normal `SEQUENCE_NOT_MATCHED` from missing signals, not a truncation problem.
