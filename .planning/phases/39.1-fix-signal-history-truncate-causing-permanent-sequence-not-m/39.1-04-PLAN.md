**Change 2:** In `_evaluate_sequence` method, after line 149 (`internal_candle_counter += 1`), add trigger timeout check:

```python
        # --- Phase 39.1 Stage 1: Trigger timeout to prevent post-trigger stall ---
        # After a strategy triggers, triggered_t blocks all events with t <= triggered_t.
        # If current_step_index == 0 (just reset after trigger), auto-reset from Plan 01
        # won't fire (it checks current_step_index > 0). This causes permanent stall.
        # Fix: Clear triggered_t after N candles to allow new sequence matching.
        if triggered_t > 0 and current_step_index == 0:
            trigger_counter = state.get("_trigger_candle_counter", 0)
            candles_since_trigger = internal_candle_counter - trigger_counter
            TRIGGER_TIMEOUT_CANDLES = 10  # Configurable later per strategy

            if candles_since_trigger > TRIGGER_TIMEOUT_CANDLES:
                logger.info(
                    f"[{symbol}] [{self.name}] [trigger_timeout] "
                    f"Clearing triggered_t={triggered_t} after {candles_since_trigger} candles "
                    f"to prevent post-trigger stall"
                )
                triggered_t = 0
                # Reset counter to prevent immediate re-fire
                state_obj.strategy_progress[self.name]["_trigger_candle_counter"] = internal_candle_counter
```

**Insertion point:** After `internal_candle_counter += 1` (line 149), BEFORE the global timeout check (line 152).

**Design decisions:**
1. Timeout-only approach (Option 4 from DEEP-ANALYSIS-OPTION4.md) — simpler and safer than reactive clearing
2. 10 candles timeout — balances safety (prevents long stalls) with correctness (prevents double-trigger)
3. INFO-level logging — notable operational event, not an error
4. Resets counter after clear — prevents timeout from firing repeatedly
5. Additive change — does not modify existing auto-reset logic from Plan 01
