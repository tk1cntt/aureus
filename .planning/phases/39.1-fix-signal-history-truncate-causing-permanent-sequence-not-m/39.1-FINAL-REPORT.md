## 🔍 NGUYÊN NHÂN GỐC RỄ (4 VẤN ĐỀ)

### **Vấn đề 1: Index-based tracking bị invalid khi log truncate** ⭐ **NGUYÊN NHÂN CHÍNH**

**Cơ chế:**
```python
# state.py - log_signal_normalize bị giới hạn 200 records
if len(self.log_signal_normalize) > 200:
    self.log_signal_normalize.pop(0)  # XÓA record đầu tiên → shift indices
```

**Code cũ (SAI):**
```python
# template.py - Dùng index để track records đã xử lý
for idx, rec in enumerate(source_records):
    if idx > last_processed_record_index:  # ← BUG!
        pending_records.append((idx, rec))
```

**Kịch bản lỗi:**
```
T0:     Match "choch_up" tại index 0 → last_processed_record_index = 0
T1-T200: 200 nến mới → log đạt 201 records → pop(0) xóa record đầu
        → Record tại index 1 → thành index 0
        → Record tại index 200 → thành index 199
        → last_processed_record_index = 0 VẪN GIỮ NGUYÊN
T201:   "sweep_bull" arrives tại index mới (sau khi shift)
        → Code check: idx (0-199) > last_processed_record_index (0)?
        → FALSE CHO TẤT CẢ! → KHÔNG PROCESS RECORD NÀO!
        → SEQUENCE_NOT_MATCHED vĩnh viễn ❌
```

**Giải pháp:**
```python
# Code mới - Dùng TIMESTAMP thay vì INDEX
for idx, rec in enumerate(source_records):
    rec_t = rec.get("t", 0)
    if rec_t >= last_processed_t:  # ← So sánh timestamp, không phụ thuộc index
        pending_records.append((idx, rec))
```

### **Vấn đề 2: Post-trigger stall - triggered_t không được clear**

**Cơ chế:**
```python
# Sau khi strategy trigger thành công
triggered_t = bar_t          # Lưu timestamp trigger
current_step_index = 0       # Reset về 0 để chờ cycle mới

# Filter events cũ
if triggered_t > 0 and latest_time <= triggered_t:
    continue  # ← SKIP tất cả events có t <= triggered_t
```

**Kịch bản lỗi:**
```
T0:     Strategy trigger tại t=1000
        → triggered_t = 1000, current_step_index = 0

T1-TN:  Events mới có t > 1000 → OK
        → Nhưng sau 200 candles, events t > 1000 bị truncate
        → Chỉ còn events có t <= 1000
        → TẤT CẢ bị skip!

        → Auto-reset check: current_step_index > 0? → FALSE (bằng 0)
        → Auto-reset KHÔNG CHẠY!
        → STALL vĩnh viễn ❌
```

**Giải pháp:**
```python
# Trigger timeout mechanism - Clear triggered_t sau N candles
if triggered_t > 0 and current_step_index == 0:
    trigger_counter = state.get("_trigger_candle_counter", 0)
    candles_since_trigger = internal_candle_counter - trigger_counter
    TRIGGER_TIMEOUT_CANDLES = cfg.trigger_timeout_candles  # 120 cho M1

    if candles_since_trigger > TRIGGER_TIMEOUT_CANDLES:
        triggered_t = 0  # ← FORCE CLEAR
```

### **Vấn đề 3: Reset signal được xử lý TRƯỚC match signal**

**Tình huống thực tế:**
- `choch_down` và `sweep_bull` xuất hiện **CÙNG 1 CANDLE**
- ORDER_FLOW_BULL cần: `choch_up` → `sweep_bull`
- `choch_down` là reset signal

**Code cũ (SAI):**
```python
for latest_signal in events_to_process:
    # Reset check TRƯỚC match
    if latest_tag in reset_tags:  # ← choch_down check trước
        reset_sequence()  # ← Reset ngay!
        break  # ← sweep_bull không được xét!

    if latest_tag == tag:  # ← sweep_bull không bao giờ được match
        match_sequence()
```

**Kịch bản lỗi:**
```
Candle X: Events = ["choch_down", "sweep_bull"] (cùng timestamp)

Step 1: Process "choch_down"
        → Reset check: choch_down trong reset_tags? → TRUE
        → RESET sequence về 0
        → break → DỪNG xử lý!

Step 2: "sweep_bull" KHÔNG BAO GIỜ được xét!
        → Strategy không trigger ❌
```

**Giải pháp:**
```python
# 3-phase processing:
# Phase 1: Collect ALL signals tại timestamp
signals_at_time = [...]

# Phase 2: Thử MATCH signals TRƯỚC (priority)
for sig in signals_at_time:
    if sig_tag == current_step_tag:
        match_signal()  # ← sweep_bull được match trước!
        matched_any_signal = True

# Phase 3: Chỉ RESET nếu KHÔNG match gì
if not matched_any_signal and has_reset_signal:
    reset_sequence()  # ← choch_down chỉ reset khi không có match
```

### **Vấn đề 4: Consumer group không được clean khi restart**

**Triệu chứng:**
- Restart service → vẫn nhận signals cũ từ lần chạy trước
- Pending entries chưa ACK được re-delivery
- State không đồng bộ

**Giải pháp:**
```python
# 3-step clean restart:
# 1. Destroy consumer group (xóa pending state)
await r.xgroup_destroy(signal_stream, group_name)

# 2. Delete signal stream (xóa stale signals)
await r.delete(signal_stream)

# 3. Create fresh consumer group từ NOW
await r.xgroup_create(signal_stream, group_name, id="$", mkstream=True)
```
