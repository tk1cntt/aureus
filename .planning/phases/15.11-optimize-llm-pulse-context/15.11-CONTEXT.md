# Phase 15.11: Optimize LLM Pulse Context — Context

**Gathered:** 2026-03-28
**Status:** Planned

<domain>
## Phase Boundary

Tối ưu phần context gửi sang LLM trong `build_pulse_context` để tạo narrative pulse ổn định theo chu kỳ ngắn, bám vào technical anchors từ `log_signal_normalize` (chỉ giữ 60 record mới nhất).

**In scope:**
- Thiết kế lại payload text của `ContextBuilder.build_pulse_context`
- Thiết kế lại system prompt cho `AIBrainClient.generate_pulse` theo hướng deterministic
- Giữ nguyên output contract JSON phẳng (`narrative`, `sentiment`, `aci`, `debate_log`)
- Bổ sung test cho stability/fallback của pulse context + parser contract

**Out of scope:**
- Đổi business logic trigger AI (`event_policy`, debounce, scheduling)
- Đổi schema output API của pulse endpoint
- Đổi mô hình LLM/backend inference
</domain>

<problem_statement>
## Current Symptom

- Payload hiện tại của `build_pulse_context` thiên về narrative tự do (`STRUCTURE/LEVELS/LIQUIDITY/METRICS`) nên dễ drift giữa các iteration dù anchors ít thay đổi.
- `generate_pulse` prompt đã có yêu cầu stability nhưng chưa có input contract đủ deterministic nên model vẫn có không gian “sáng tạo”.
- Dữ liệu đầu vào thực tế đã chuyển sang `log_signal_normalize` rolling window 60 item, nhưng context chưa tận dụng cấu trúc này làm anchor cứng.
</problem_statement>

<hypotheses>
## Working Hypotheses

1. Nếu payload được chuẩn hóa theo “anchor blocks + fixed ordering + bounded length”, độ dao động narrative sẽ giảm rõ rệt.
2. Nếu system prompt nêu explicit priority rule (newest-first, no-new-claim-without-anchor), output sẽ nhất quán hơn mà vẫn giữ thông tin hữu ích.
3. Nếu thêm test kiểm tra shape/context invariants thì regression drift sẽ được phát hiện sớm.
</hypotheses>

<investigation_path>
## Investigation Path

- Checkpoint A: Chốt nguồn dữ liệu chuẩn từ `state.signal_history_normalized` (cap 60) và mapping fields cần đưa vào pulse context.
- Checkpoint B: Chốt text template deterministic cho payload (header, anchor summary, trigger focus, confidence guards).
- Checkpoint C: Chốt prompt contract cho `generate_pulse` giữ JSON phẳng + limit sentence count.
- Checkpoint D: Bổ sung verification cho context builder và pulse parser fallback.
</investigation_path>

<expected_outputs>
## Expected Outputs for Next Steps

- Context template mới cho pulse dựa trên 60 normalized events.
- Prompt spec rõ ràng để hạn chế creativity drift.
- Verification map (unit/integration nhẹ) cho stability và output contract.
</expected_outputs>
