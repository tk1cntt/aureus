## Task 1: Create State Machine Circuit Breaker
<read_first>
- services/aureus-signal/common/logging_common.py
</read_first>
<action>
Create file `services/aureus-signal/common/circuit_breaker.py` containing a `CircuitBreaker` utility class.
Specs:
- Must maintain a state enum: `CLOSED` (normal), `OPEN` (tripped), `HALF_OPEN` (testing recovery).
- Initialize with `error_threshold=5` and `timeout_seconds=60`.
- Methods required:
  - `record_success()`: If state is `HALF_OPEN`, switches back to `CLOSED`. Resets failure count.
  - `record_failure()`: Inflicts a failure. If state is `CLOSED` and failure count >= `error_threshold`, state transitions to `OPEN` and `last_failure_time` is recorded.
  - `can_execute() -> bool`: Returns `True` if `CLOSED`. Returns `False` if `OPEN` and `(now - last_failure_time) < timeout`. Returns `True` and switches to `HALF_OPEN` if `OPEN` and timeout elapsed.

Create unit tests in `services/aureus-signal/tests/test_circuit_breaker.py` validating state transitions.
</action>
<acceptance_criteria>
- `services/aureus-signal/common/circuit_breaker.py` exists and contains exactly the states specified.
- `pytest services/aureus-signal/tests/test_circuit_breaker.py` successfully passes and tests OPEN/CLOSED transition.
</acceptance_criteria>

## Task 3: TradingAgents Circuit Breaker & Async Observer
<read_first>
- services/aureus-signal/engine/providers/tradingagents.py
</read_first>
<action>
Modify `services/aureus-signal/engine/providers/tradingagents.py`.
1. Integrate the new `CircuitBreaker`. Initialize it inside `TradingAgentsProvider`.
2. In the `get_decision_async()` fetching logic:
   - Wrap the HTTP call. Check `self.circuit_breaker.can_execute()`.
   - If `False`, immediately return a Fallback/Error state (e.g., skip signal evaluation or return zero/`None`) without blocking.
   - If HTTP call fails or timeouts, call `record_failure()` and return Fallback.
   - If it succeeds, call `record_success()`.
3. Add the **Async Observer**: use `asyncio.create_task(log_ta_drift(...))` so that checking the drift difference and logging it to TimescaleDB is non-blocking to the main loop.
</action>
