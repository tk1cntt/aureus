# Phase 15: Strategy Migration & Unification - Execution Plan

<objective>
Migrate legacy hardcoded strategies (`TrendContinuationStrategy`, `OrderFlowDominanceStrategy`) to `TemplateStrategy` by enriching the config-driven engine with `context_filters` (for pre-conditions) and dynamic `trade_execution` variables (risk sizing). Make `TemplateStrategy` the universal engine and delete old implementations.
</objective>

<requirements>
- SEQ-03 (Implement Context Evaluator for TemplateStrategy)
- SEQ-04 (Support dynamic Trade Execution JSON for TemplateStrategy)
</requirements>

<must_haves>
- `TemplateStrategy` correctly parses and applies `context_filters` from JSON config.
- `TemplateStrategy.build_order_plan` properly inherits JSON parameters (`size`, `sl`, `tp`, `trailing`).
- `StrategyRegistry` no longer instantiates legacy classes.
- Legacy files are deleted.
- Postgres `config` JSON seeds use the new structure.
</must_haves>

## Wave 1: Context Evaluator & TemplateStrategy Enhancement

<task id="15-01-01" status="pending">
<read_first>
- `services/aureus-signal/engine/strategies/template.py` (Source of Truth for engine structure)
- `.planning/phases/15-strategy-migration-unification/15-CONTEXT.md` (Design specifications for Context Filters)
</read_first>

<action>
Modify `services/aureus-signal/engine/strategies/template.py` to add context filtering and enhanced trade execution.
1. In `__init__`, parse `config.get("context_filters", [])` and `config.get("trade_execution", {})`.
2. Add a `_evaluate_context(self, state_obj: Any) -> bool` method. It must handle list of filters:
   - `[{"type": "trend_alignment", "required_trend": "BULLISH"}]` -> checks `state_obj.htf_trend`
   - `[{"type": "session_active", "allowed": ["LONDON", "NEW_YORK"]}]` -> checks `state_obj.current_session`
   - `[{"type": "ob_imbalance", "min_ratio": 3.0}]` -> computes dominant ratio from `state_obj.obs`
   - `[{"type": "ema_alignment", "required_slope": "POSITIVE", "period": 21}]` -> checks `state_obj.emas.get(21)['slope']`
3. Update `_evaluate_sequence` or `evaluate`/`on_bar_close` to ensure that if `_evaluate_context` returns `False`, the signal sequence can reset if necessary, or at the minimum, the strategy DOES NOT emit an actionable reason code.
4. Update `build_order_plan` on `TemplateStrategy` to override `BaseStrategy.build_order_plan`. It should read `self.trade_execution` configuration properties and inject:
   - `size`, `sl`, `tp`, `trailing` values directly into the output plan.
</action>

<acceptance_criteria>
- `TemplateStrategy` source code contains `_evaluate_context` implementation.
- `TemplateStrategy` source code contains `build_order_plan` override reading `self.trade_execution`.
- Testing `obj_instance._evaluate_context(mock_state)` runs successfully.
</acceptance_criteria>
</task>
