## Summary

Phase 44.4 nên được thực hiện theo chiến lược **safe-first optimization**: tối ưu data access trong `StructureSignal` trước, chạy shadow/parity song song, sau đó mới cân nhắc incremental path. Điều này phù hợp với ràng buộc “strict parity” và kiến trúc hiện tại nơi `structure_processor` là upstream của CHOCH/OB/sweep outlets. [VERIFIED: signal_factory.py ordering + 44.4 requirements]

Từ code hiện tại, bottleneck có khả năng cao đến từ việc quét nhiều lớp trên full DataFrame mỗi candle (`t_map` rebuild, `_process_choch` scan forward, `_verify_mitigations` lọc + `iterrows`). Đây là dạng chi phí tăng theo window size và số swing points/OB tích lũy. [VERIFIED: structure.py]

Khuyến nghị chính: triển khai theo 3 lớp an toàn: **(1) Data-access optimization thuần cơ học**, **(2) Shadow/parity verifier có auto-fallback**, **(3) Incremental processing chỉ bật sau khi parity ổn định ở shadow window định nghĩa trước**. [VERIFIED: 44.4-STRUCTURE-OPT-REQUIREMENTS.md]

**Primary recommendation:** Ưu tiên A + D (data-access + shadow parity), chưa bật incremental B cho production path cho đến khi mismatch=0 trên cửa sổ replay + live shadow đã khóa trước. [VERIFIED: 44.4-STRUCTURE-OPT-REQUIREMENTS.md]

## Baseline Bottleneck Hypotheses

1. **Rebuild `t_map` mỗi lần `calculate()`** gây overhead O(window) lặp lại cho mỗi candle. [VERIFIED: structure.py dòng tạo `t_map`]
2. **`_verify_mitigations` dùng `search_df = df[df['t'] > t_breakout]` + `iterrows()`** tạo object overhead Pandas lớn khi OB nhiều. [VERIFIED: structure.py]
3. **`_process_choch` + `_process_ob` dùng nhiều `df.iloc[j]` trong loop Python** có overhead truy cập scalar cao. [VERIFIED: structure.py]
4. **Full re-scan tất cả pivot chưa CHOCH mỗi candle** có thể vượt budget khi `swing_points` tăng theo thời gian. [VERIFIED: structure.py]
5. **Logging info dày đặc trong hot path** có thể góp phần latency spike theo I/O logger backend. [VERIFIED: structure.py + manager.py/live_engine pattern]

### Pattern 1: Shadow-first Dual Path
**What:** Chạy old path + new path trong `shadow` mode, old path vẫn quyết định output production; new path chỉ để đo latency và so sánh contract. [VERIFIED: 44.4 requirements doc]
**When to use:** Mọi tối ưu ảnh hưởng signal semantics hoặc state mutation. [VERIFIED: strict parity objective]

### Pattern 2: Contract-based Parity Comparator
**What:** So sánh đầy đủ output contract: `tag`, `t`, `breakout_t`, OB fields (`top`, `bottom`, `t_start`, `t_breakout`, `quality`, mitigation flags), và side effects (`transient_signals`, `obs` delta). [VERIFIED: structure.py fields + 44.4 requirements]
**When to use:** Trước khi promote từ shadow sang on. [VERIFIED: 44.4 requirements]

### Pattern 3: Guarded Incremental Processing
**What:** Lưu watermark/index nội bộ cho pivot/OB đã scan; khi phát hiện out-of-order/reset/warmup mismatch thì hard fallback full scan. [ASSUMED]
**When to use:** Chỉ sau khi A + D ổn định và profiling chứng minh còn bottleneck lớn. [VERIFIED: recommendation in 44.4 requirements]

### Anti-Patterns to Avoid
- **Direct replace path (no shadow):** dễ gây logic drift không phát hiện sớm. [VERIFIED: strict parity + adversarial section]
- **Comparator nông (chỉ so tag):** tạo false negative parity, bỏ sót drift ở metadata/state. [VERIFIED: 44.4 requirements]
- **Bật incremental sớm:** dễ state drift trong recovery/backfill/recalc paths. [VERIFIED: live_engine has recovery/recalculate complexity]

## Acceptance Criteria (đo được)

1. **Parity correctness:** mismatch count = 0 trên replay chuẩn và live shadow window tối thiểu N candles/symbol (N cần lock ở planning). [ASSUMED]
2. **Signal contract stability:** không đổi schema output/side effects (`transient_signals`, `obs`, `swing_points` mutation behavior) so với baseline. [VERIFIED: 44.4 requirements]
3. **Performance gain:** `structure_processor` avg latency giảm >= 40% trong điều kiện benchmark tương đương. [VERIFIED: 44.4 requirements]
4. **Safety rollback:** khi mismatch xuất hiện, mode tự động về old-path xử lý production trong cùng process uptime. [ASSUMED]
5. **No regression throughput:** `_total` per-candle không tăng trong mode `on`; shadow overhead được giới hạn bởi budget định nghĩa trước. [VERIFIED: 44.4 requirements intent]

**What goes wrong:** Tốn effort nhưng latency không giảm đáng kể. [ASSUMED]

### Pitfall 2: Drift do khác biệt type/precision
**What goes wrong:** Kết quả break/mitigation lệch 1 candle do float/int cast. [VERIFIED: adversarial section]
**How to avoid:** Comparator normalize rõ type và tolerance policy (nếu có). [ASSUMED]

### Pitfall 3: Incremental state không đồng bộ với recovery path
**What goes wrong:** Live ổn nhưng recalculate/backfill tạo output khác. [VERIFIED: live_engine có nhiều path state rebuild]
**How to avoid:** Test replay cho cả init warmup + delta + recalc. [VERIFIED: code paths exist]
