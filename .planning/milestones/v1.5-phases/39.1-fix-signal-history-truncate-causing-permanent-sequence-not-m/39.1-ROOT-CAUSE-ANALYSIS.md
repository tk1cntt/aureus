## Root Cause: Auto-Reset Logic Gap

### What Phase 39.1 Fixed ✅

Phase 39.1 correctly implemented auto-reset for **mid-sequence stalls** (D-01):

```python
# template.py line 332-380
if current_step_index > 0 and triggered_t > 0:
    events_after_trigger = sum(1 for rec in source_records if rec["t"] > triggered_t)
    if events_after_trigger < remaining_steps:
        # Auto-reset fires → resets to step 0
```

This works when:
- Strategy is mid-sequence (e.g., matched step 1 of 3, `current_step_index = 1`)
- History truncation removes all events newer than `triggered_t`
- Auto-reset detects insufficient events and resets to step 0

### The Critical Gap ❌

**After a strategy successfully triggers**, the following happens:

1. **`evaluate()` method (line 517-522)** calls `_reset_sequence_state`:
   ```python
   self._reset_sequence_state(
       state_obj,
       triggered_t=bar_t,  # ← Sets triggered_t to trigger timestamp
       last_processed_t=...,
       internal_candle_counter=...,
   )
   ```

2. **`_reset_sequence_state()` (line 444-471)** sets:
   ```python
   state_obj.strategy_progress[self.name] = {
       "current_step_index": 0,  # ← Reset to 0
       "triggered_t": triggered_t,  # ← Set to bar_t (e.g., 1775850060)
       ...
   }
   ```

3. **On next candles**, `_evaluate_sequence()` processes events:
   ```python
   # Line 237-241
   if triggered_t > 0 and latest_time <= triggered_t:
       logger.debug(...)
       continue  # ← SKIP ALL events with t <= triggered_t
   ```

4. **The problem:**
   - `current_step_index == 0` (just reset after trigger)
   - `triggered_t = 1775850060` (large timestamp from trigger)
   - ALL events in history have `t <= 1775850060` (they're older than trigger time)
   - **Every event gets skipped** at line 237
   - Auto-reset guard at line 332 checks `if current_step_index > 0` → **FALSE**
   - **Auto-reset NEVER fires** because we're already at step 0

### Timeline of Failure

```
T0: Strategy starts → triggered_t=0, current_step_index=0
    → All events valid for matching ✅

T1: Strategy matches sequence → triggers at bar_t=1775850000
    → _reset_sequence_state(triggered_t=1775850000)
    → current_step_index=0, triggered_t=1775850000

T2: New candle arrives (t=1775850060)
    → History contains events with t <= 1775850060
    → Event filter: if triggered_t > 0 and latest_time <= triggered_t:
    → ALL events skipped (all have t <= 1775850060 which is close to triggered_t)
    → current_step_index stays 0
    → Auto-reset check: if current_step_index > 0 → FALSE → no reset
    → Result: SEQUENCE_NOT_MATCHED ❌

T3, T4, ...: Same as T2 → PERMANENT STALL
```

### Why This Happens

The auto-reset logic (D-01) was designed to fix **mid-sequence stalls** but didn't consider **post-trigger stalls**:

| Scenario | current_step_index | triggered_t | Auto-reset fires? | Problem? |
|----------|-------------------|-------------|-------------------|----------|
| Mid-sequence stall | > 0 | > 0 | ✅ YES | Fixed by D-01 |
| Post-trigger stall | 0 | > 0 | ❌ NO | **NOT FIXED** ← This is the gap! |
| Normal matching | 0 | 0 | ❌ NO (correct) | No problem |

## Solution: Fix the Gap

We need to handle the case where `current_step_index == 0` but `triggered_t > 0` and ALL events are being skipped.

### Option 1: Reset triggered_t After Timeout (Recommended)

Add a timeout mechanism to clear `triggered_t` after N candles, allowing new events to be processed:

```python
# In _evaluate_sequence, BEFORE the event processing loop
if triggered_t > 0 and current_step_index == 0:
    # Check how many candles have passed since trigger
    candles_since_trigger = internal_candle_counter - state.get("trigger_candle_counter", 0)
    max_wait_candles = 10  # Allow 10 candles to pass before clearing triggered_t
    
    if candles_since_trigger > max_wait_candles:
        logger.info(
            f"[{symbol}] [{self.name}] [clear_triggered_timeout] "
            f"triggered_t={triggered_t} set {candles_since_trigger} candles ago, "
            f"clearing to allow new sequence matching"
        )
        triggered_t = 0  # Clear so new events can be matched
```

**Pros:**
- Simple, predictable
- Prevents immediate re-triggering (still waits 10 candles)
- Doesn't depend on history size

**Cons:**
- Arbitrary timeout value (10 candles)
- May clear too early or too late depending on timeframe

### Option 2: Clear triggered_t When All Events Are Skipped

Detect when ALL pending events are being skipped due to `triggered_t` and clear it:

```python
# In _evaluate_sequence, after the pending_records loop
if triggered_t > 0 and current_step_index == 0:
    # Count how many events were skipped due to triggered_t
    skipped_count = 0
    processed_count = 0
    for record_idx, record in pending_records:
        # ... existing event processing ...
        for latest_signal in events_to_process:
            latest_time = latest_signal.get("t")
            if triggered_t > 0 and latest_time <= triggered_t:
                skipped_count += 1
            else:
                processed_count += 1
    
    # If ALL events were skipped and we're at step 0, clear triggered_t
    if skipped_count > 0 and processed_count == 0:
        logger.warning(
            f"[{symbol}] [{self.name}] [clear_triggered_all_skipped] "
            f"All {skipped_count} events skipped due to triggered_t={triggered_t}, "
            f"clearing to unblock sequence matching"
        )
        triggered_t = 0
```

**Pros:**
- Reactive — only clears when actually blocked
- No arbitrary timeout

**Cons:**
- More complex logic
- Requires counting skipped events

### Option 3: Hybrid Approach (Best)

Combine both approaches:
1. Clear `triggered_t` when all events are skipped (Option 2)
2. Also add a safety timeout as backup (Option 1)

This provides both reactive and proactive protection.

## Recommended Fix

- Timeout: 10 candles (configurable per strategy later)
- All-skipped detection: Check if `len(pending_records) > 0` but `processed_count == 0`
