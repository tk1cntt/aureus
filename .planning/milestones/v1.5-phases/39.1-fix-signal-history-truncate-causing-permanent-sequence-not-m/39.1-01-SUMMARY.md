# Phase 39.1 Plan 01: Auto-reset for Truncation Stall Summary

## One-liner

Implemented auto-reset detection in `_evaluate_sequence` that resets sequence state when signal history truncation leaves fewer usable events than remaining steps needed, preventing permanent SEQUENCE_NOT_MATCHED stall after ~4h runtime.

## What Was Built

### Problem
Signal history truncation (`log_signal_normalize` bounded at 240 records) combined with `triggered_t` filtering causes permanent SEQUENCE_NOT_MATCHED after ~4h of M15 candle processing. Once all events in the truncated history have `t <= triggered_t`, the sequence evaluator skips every event forever.

### Solution
Added auto-reset detection between the event processing loop and the "Compute results" section in `_evaluate_sequence`:

- **Condition**: `current_step_index > 0 AND triggered_t > 0 AND events_after_trigger < remaining_steps`
- **Action**: Calls `_reset_sequence_state` with `triggered_t=0`, resets local variables, returns early with consistent state
- **Guard**: `triggered_t > 0` prevents false resets during normal step matching (added as deviation from original plan which only checked `current_step_index > 0`)
- **Logging**: WARNING level with event count and remaining step count
