# Phase 40.3: Fix Stale Signal Trigger on Service Restart — Context

**Gathered:** 2026-04-13
**Status:** Ready for planning
**Source:** Prior discussion + intel analysis

<domain>
## Phase Boundary

Thêm suppress flag vào signal service để ngăn signals/strategies trigger trên stale data khi service restart. Flag được set True khi startup, reset False khi nhận candle real-time đầu tiên từ gateway stream.

Phase chỉ thay đổi `live_engine.py` — không sửa signal calculators, strategy evaluators, hay test files.
</domain>

<decisions>
## Implementation Decisions

### Suppress Flag Design (LOCKED)
- Thêm attribute `_signal_suppressed = True` trên SymbolState sau khi hydrate snapshot
- Trong delta candle loop: signals vẫn được calculate nhưng KHÔNG emit/transient/publish khi flag = True
- Khi candle đầu tiên từ gateway stream đến: set `_signal_suppressed = False` → hoạt động bình thường
- Flag KHÔNG serialize trong `to_dict()` — ephemeral, chỉ tồn tại trong memory

### Scope (LOCKED)
- Chỉ sửa `live_engine.py` — tối đa 1 file
- Không sửa signal calculators (cisd.py, fvg.py, cisd_mtf.py, ...)
- Không sửa strategy evaluators (template.py, registry.py)
- Không sửa state.py, state_snapshot.py
- Không sửa notifier/formatters

### Suppression Points (LOCKED)
Flag chặn tại 2 điểm publish trong live_engine.py:
1. `publish_signal_event` call (line ~748) — check flag trước khi publish SIGNAL_EVENT
2. Strategy evaluation via `evaluate_all` — chỉ gọi khi flag = False (hoặc gọi với backfill_status=WARMING)

### Reset Trigger (LOCKED)
Flag reset khi:
- Nhận candle M1 đầu tiên từ gateway stream (line ~697 của live_engine.py)
- Candle có timestamp > last_snapshot_time (candle thực sự mới, không phải stale replay)

### Delta Loop Behavior (LOCKED)
- Delta candles vẫn được process (window update + signal calculation) — không skip
- `transient_signals` được clear sau delta loop (defensive cleanup)
- Strategy `evaluate_all` KHÔNG gọi trong delta loop khi flag = True

### Not In Scope
- Recalculation path (integrity_and_recalc_task) — xử lý sau nếu cần
- Zombie strategy sequences — chấp nhận, expire tự nhiên qua max_length
- State serialization inconsistency (cisd_tracker) — phase riêng

### Trade-offs Accepted
- Delta candles vẫn tốn CPU cho signal calculation — acceptable (short-lived)
- Signal đầu tiên từ candle real-time có thể bị delay 1 tick — negligible
- Không bảo vệ recalculation false signals — edge case, fix sau
</decisions>

## Specific Implementation Details

### Code locations in live_engine.py:

1. **Set flag** — after snapshot restore (~line 369):
   ```python
   state._signal_suppressed = True
   ```

2. **Clear transient_signals after delta loop** — after line 404:
   ```python
   state.transient_signals = {}
   ```

3. **Suppress publish** — before `publish_signal_event` (~line 740-748):
   ```python
   if not getattr(state, "_signal_suppressed", False) and getattr(state, "transient_signals", None):
       # ... publish logic
   ```

4. **Suppress evaluate_all during startup** — line 474:
   - Do NOT call `evaluate_all` while `_signal_suppressed = True`
   - Only call after flag is cleared

5. **Reset flag on first gateway candle** — in main stream loop (~line 697):
   ```python
   if getattr(state, "_signal_suppressed", False):
       state._signal_suppressed = False
   ```

### Flow after fix:
```
Service start
  → Hydrate snapshot → _signal_suppressed = True
  → Process delta candles → calculate but suppress emit
  → evaluate_all SKIPPED (suppressed)
  → transient_signals cleared
  → "Engine ready"
  → Wait for gateway...
  → First candle arrives → _signal_suppressed = False
  → Process normally → emit signals → publish Telegram
```
</specifics>
