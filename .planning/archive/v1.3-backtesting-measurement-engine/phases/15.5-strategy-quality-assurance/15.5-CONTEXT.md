# Phase 15.5: Strategy Quality Assurance - Context

**Gathered:** 2026-03-23
**Status:** Ready for planning

<domain>
## Phase Boundary

Validate strategy correctness and quality INDEPENDENTLY before Nautilus integration. Establish replay baselines so that poor backtest results in later phases can be attributed correctly — strategy problem vs signal pipeline problem vs Nautilus integration problem.

**This phase does NOT:**
- Build any Nautilus integration (Phase 17)
- Modify strategy logic or signal pipeline
- Create UI or API endpoints
- Set up database schemas for backtest results (Phase 16)

</domain>

<decisions>
## Implementation Decisions

### Test Data Source
- **D-01:** Hybrid approach — TimescaleDB `aureus_candles` directly for `strategy_replay.py`, exported CSV files for unit/scenario tests (deterministic, CI-friendly)

### Export Scope
- **D-02:** Export 2000 bars per symbol, for ALL symbols currently in the database. CSV files committed to repo as frozen test datasets.

### Baseline Report
- **D-03:** Tier 2 baseline per strategy per symbol:
  - Trigger count and trigger rate (triggers / total bars)
  - Reject count + reject reason breakdown
  - Score distribution (min, max, avg)
  - Signal contribution — which signal tags trigger most frequently
  - Trigger timing — distribution by session (LONDON, NEW_YORK, ASIA, etc.)
  - Context filter pass/fail breakdown

### Strategy Coverage
- **D-04:** 3 seed strategies (TREND_CONT, SESSION_SWEEP, ORDER_FLOW_DOM) have dedicated tests with known expected behavior assertions. Additionally, extensible test framework supports any custom TemplateStrategy JSON config with basic validation (trigger count > 0, determinism check).

### Replay Output
- **D-05:** Replay results persist to TimescaleDB (dedicated table for replay results — separate from backtest results in Phase 16)
- **D-06:** CLI supports 3 modes:
  - Single: `--symbol XAUUSD --strategy TREND_CONT`
  - Batch: `--symbol XAUUSD` (runs all registered strategies)
  - Full matrix: no args (all symbols × all strategies)

### Agent's Discretion
- DB table schema for replay results — agent decides structure aligned with Tier 2 metrics
- CSV export script implementation — agent decides tooling (Python script or SQL COPY)
- Test file organization — agent decides grouping within `tests/` directory

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `execute_signals_for_candle(signals, df, state, symbol, redis_client)`: Runs all 18 signals per candle — core of replay pipeline. Redis param can be mocked/None for offline replay.
- `EngineRegistry.auto_load_signals()`: Auto-discovers and loads signal modules from `engine.signals` package
- `StrategyRegistry.evaluate_all(df, signals, state_obj)`: Runs all registered strategies, returns accepted intents + buffers rejections
- `SymbolState`: Full state tracking (atr, emas, trend, regime, session, obs, signal_history, strategy_progress)
- `MockState` class in existing tests: Lightweight state stub for unit tests

### Established Patterns
- `_o1` parity tests: Run signal on known data, assert exact output — use this pattern for strategy determinism tests
- `_integration_execute_signals_for_candle` tests: Full pipeline integration — use this pattern for scenario tests
- CSV data loading in tests: Several existing tests load pandas DataFrames from inline data — extend to external CSV

### Integration Points
- `aureus_candles` TimescaleDB table: Source of truth for historical candle data (used by replay tool)
- `seed_system_strategies()` function: Provides strategy configs — replay tool should load strategies from DB or seed file
- Strategy configs stored in `aureus_strategy_templates` table: Load via DB query for extensible testing

</code_context>
