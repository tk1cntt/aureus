# Report 260513-8z8: Pending fill không gửi gateway trong AureusProvider_v2

## Kết luận ngắn

Pending order đã khớp nhưng gateway không nhận `ORDER_FILLED` có 3 nhóm nguyên nhân khác nhau:

1. **Không gửi event thật sự**: `OnTradeTransaction` return trước `PushOrderFilled`. Gate mạnh nhất: socket mất kết nối tại `g_socket.IsConnected()` hoặc provider không nhận/không nhận dạng deal là pending fill.
2. **Có gửi event nhưng thiếu correlation**: `PopPendingOrderMapping(orderTicket, ...)` không tìm thấy mapping thì `cmd_id` rỗng, `trace_id` chỉ còn phụ thuộc MT5 deal comment. Trường hợp này **không chặn gửi** `ORDER_FILLED`, nhưng làm gateway/journal khó nối lifecycle nếu comment không mang trace.
3. **Có gọi send nhưng gateway không nhận/không biết send fail**: `PushOrderFilled` gọi `g_socket.SendJSON(json)` nhưng không kiểm tra kết quả gửi. Nếu `SendJSON` fail nội bộ hoặc socket hỏng sau `IsConnected()`, provider chỉ log `ORDER_FILLED pushed` khi debug, không có bằng chứng gateway nhận.

Kết luận ưu tiên: cần bổ sung log/test trước khi sửa rộng. Fix nhỏ rõ nhất nếu sửa sau: thêm log diagnostic cho mọi early-return trong `OnTradeTransaction` pending-fill path và kiểm tra/log kết quả `g_socket.SendJSON` trong `PushOrderFilled` nếu API trả trạng thái.

## Flow hiện tại

1. Gateway gửi command open order vào provider.
2. `ExecuteOpenOrder` gửi lệnh pending sang MT5.
3. Khi pending accepted và chưa có terminal event, provider lưu mapping:
   - File: `D:/Aureus/mql5/AureusProvider_v2.mq5:3282-3288`
   - Code path: `StorePendingOrderMapping((long)result.order, traceId, cmdId, comment, strategyName)` rồi `PushOrderOpened(...)`.
   - Key mapping là `result.order`, tức MT5 pending order ticket.
4. MT5 khớp pending order và gọi `OnTradeTransaction`.
5. `OnTradeTransaction` chỉ xử lý `TRADE_TRANSACTION_DEAL_ADD`.
6. Provider select deal bằng `HistoryDealSelect(trans.deal)`.
7. Provider chỉ tiếp tục nếu `DEAL_ENTRY` là `DEAL_ENTRY_IN` hoặc `DEAL_ENTRY_OUT`.
8. Provider bỏ qua deal có `DEAL_MAGIC == 0`.
9. Provider lấy `DEAL_ORDER` vào `orderTicket`.
10. Trước pending-fill branch, provider yêu cầu `g_socket.IsConnected()`.
11. Với `DEAL_ENTRY_IN`, provider `HistoryOrderSelect(orderTicket)` rồi lấy `ORDER_TYPE`.
12. Nếu `ORDER_TYPE` là pending (`BUY_LIMIT`, `SELL_LIMIT`, `BUY_STOP`, `SELL_STOP`, `BUY_STOP_LIMIT`, `SELL_STOP_LIMIT`) thì coi là pending fill.
13. Provider pop mapping bằng key `orderTicket`: `PopPendingOrderMapping(orderTicket, mappedTraceId, mappedCmdId, mappedComment, mappedStrategyName)`.
14. Nếu mapping có, provider dùng mapping để bổ sung `traceId`, `dealComment`, `strategyName`, và truyền `mappedCmdId` vào `PushOrderFilled`.
15. `PushOrderFilled` build JSON `ORDER_FILLED` gồm `pending_order_id`, `position_ticket`, `deal_ticket`, `trace_id`, `cmd_id`, `comment`, rồi gọi `g_socket.SendJSON(json)`.

## Giả thuyết ưu tiên

1. **Socket disconnect tại thời điểm fill**
   - Lý do: gate `!g_socket.IsConnected()` return trực tiếp trước pending detection và không có replay queue.
   - Dấu hiệu cần tìm: timer log `Still disconnected`, thiếu log `ORDER_FILLED pushed`, gateway không có event.
   - Mức giải thích: đầy đủ cho “pending khớp nhưng không gửi gateway”.

2. **History order select/type không nhận dạng pending fill**
   - Lý do: `ORDER_FILLED` chỉ gửi nếu `HistoryOrderSelect(DEAL_ORDER)` thành công và `ORDER_TYPE` là pending. Nếu `DEAL_ORDER` không select được, `orderType = -1`, `isPendingFill = false`, return.
   - Dấu hiệu cần tìm: có deal entry in, magic != 0, nhưng không có log pending detected. Hiện thiếu log nên cần bổ sung diagnostic.
   - Mức giải thích: đầy đủ.

3. **HistoryDealSelect hoặc DEAL_ENTRY/MAGIC gate return sớm**
   - Lý do: cả 3 gate return không log.
   - Dấu hiệu cần tìm: MT5 history có deal nhưng provider không log pending detected. Cần log condition để phân biệt.
   - Mức giải thích: đầy đủ nếu xảy ra.

4. **SendJSON fail sau khi đã qua `IsConnected()`**
   - Lý do: `PushOrderFilled` không kiểm tra kết quả send. Nếu send thất bại, provider không biết.
   - Dấu hiệu cần tìm: provider log `ORDER_FILLED pushed` nhưng gateway không thấy JSON.
   - Mức giải thích: đầy đủ cho “provider nghĩ đã gửi nhưng gateway không nhận”.

5. **Mapping `pending_order_id -> trace_id/cmd_id` mất/mismatch**
   - Lý do: mapping bounded FIFO theo `InpMaxCmdIdHistory`, RAM-only, pop bằng `DEAL_ORDER`. Restart EA hoặc quá cap làm mất mapping; `DEAL_ORDER` mismatch cũng làm miss.
   - Dấu hiệu cần tìm: `ORDER_FILLED` có `pending_order_id`, `position_ticket`, `deal_ticket` nhưng `cmd_id`/`trace_id` rỗng.
   - Mức giải thích: không giải thích “không gửi gateway”; chỉ giải thích “gateway/journal nhận nhưng không correlate” nếu event có tới gateway.

## Khuyến nghị

1. **Không sửa logic rộng ngay.** Trước tiên thêm observability nhỏ trong `OnTradeTransaction`:
   - Log khi return do `trans.type` không phải `TRADE_TRANSACTION_DEAL_ADD` chỉ khi liên quan order/deal có id.
   - Log `HistoryDealSelect` fail với `trans.deal`.
   - Log `entry`, `magic`, `orderTicket`, `HistoryOrderSelect` result, `orderType`, `isPendingFill`.
   - Log socket disconnected tại transaction fill path, không chỉ timer.

2. **Sửa nhỏ mục tiêu nếu được approve:** trong `PushOrderFilled`, nếu `g_socket.SendJSON` có return status thì check và log failure. Nếu API không return bool, thêm gateway ACK/reconcile hoặc outbound send diagnostic ở socket wrapper.

3. **Test/verify sau khi sửa source:**
   - Compile MQL5 theo build rules hiện có.
   - Chạy scenario pending limit fill.
   - Kiểm tra provider log có `OnTradeTransaction: pending DEAL_ENTRY_IN detected`.
   - Kiểm tra gateway log nhận JSON `ORDER_FILLED` có đủ `pending_order_id`, `position_ticket`, `deal_ticket`, `trace_id`, `cmd_id`, `comment`, `strategy_name`.
   - Kiểm tra journal DB chuyển `TRIGGERED -> EXECUTED` nếu backend liên quan.
   - Nếu chạm DB trong fix sau, phải chạy E2E DB theo `D:/Aureus/CLAUDE.md`.

4. **Nếu không muốn thêm log:** chạy manual trace bằng MT5 journal + gateway raw socket log để phân biệt 3 case:
   - Không có `ORDER_FILLED pushed` → fail trước `PushOrderFilled`.
   - Có `ORDER_FILLED pushed` nhưng gateway không nhận → send/socket issue.
   - Gateway nhận `ORDER_FILLED` nhưng DB không update → correlation/payload/backend issue.
