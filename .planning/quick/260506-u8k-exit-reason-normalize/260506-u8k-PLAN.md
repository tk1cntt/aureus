# Quick Task 260506-u8k: Exit Reason Normalize Plan

<objective>
Analyze `mql5/AureusProvider_v2.mq5::PushOrderClosed`, verify close payload fields, and fix reason normalization so closed trades do not all become `MANUAL_CLOSE`.
</objective>

<context>
Initial inspection found:

- `PushOrderClosed` sends `close_price` and `t`, but not explicit `exit_reason` / `close_reason`.
- Gateway fills `exit_time` from `t` for `ORDER_CLOSED`, but `OrderClosedEvent` has no reason field, so any provider reason would be dropped unless schema changes.
- Trader journal reads `event.get("close_reason", event.get("reason", ""))`, then `_normalize_exit_reason`; blank reason becomes `MANUAL_CLOSE`.

Assumption: MT5 provider should derive reason from close deal metadata when possible. Candidate MT5 reasons to support include TP, SL, SO/stop-out, client/mobile/web/expert close, and existing text aliases.
</context>
